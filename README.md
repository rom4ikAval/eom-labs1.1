# eom-labs1.1
## 1. Розміри типів даних

| Тип | Розмір, bytes | Розмір, bits |
|---|---:|---:|
| char | 1 | 8 |
| short | 2 | 16 |
| int | 4 | 32 |
| long | 8 | 64 |
| long long | 8 | 64 |
| float | 4 | 32 |
| double | 8 | 64 |
| void * | 8 | 64 |

Типи займають різну кількість пам'яті. У дослідженому середовищі
int займає 32 біти, а вказівник void * — 8 байтів.
Розмір вказівника відповідає 64-бітному представленню адрес
у цьому середовищі. Розміри деяких типів залежать від платформи.

## 2. Представлення чисел

| Decimal | Hexadecimal | Binary |
|---:|---|---|
| 10 | 0xA | 00001010 |
| 65 | 0x41 | 01000001 |
| 127 | 0x7F | 01111111 |
| 255 | 0xFF | 11111111 |
| 256 | 0x100 | 100000000 |
| 1024 | 0x400 | 10000000000 |

65, 0x41 та двійковий запис 01000001 позначають однакове
числове значення в різних системах числення.

## 3. Виведення бітів

| Decimal | Hex | Binary |
|---:|---|---|
| 0 | 0x00 | 00000000 |
| 1 | 0x01 | 00000001 |
| 10 | 0x0A | 00001010 |
| 65 | 0x41 | 01000001 |
| 127 | 0x7F | 01111111 |
| 128 | 0x80 | 10000000 |
| 255 | 0xFF | 11111111 |

Функція починає з біта 7, щоб вивести старший біт першим,
а молодший — останнім. Це звичний порядок запису двійкового числа.

## 4. Символи

| Character | Decimal | Hex |
|---|---:|---|
| A | 65 | 0x41 |
| B | 66 | 0x42 |
| a | 97 | 0x61 |
| 0 | 48 | 0x30 |
| 9 | 57 | 0x39 |

У змінній char c = 'A' зберігається числовий код символу.
У дослідженому середовищі код A дорівнює 65.

## 5. Signed та unsigned

| Тип | Значення | Hex байта | Біти |
|---|---:|---|---|
| int8_t | -1 | 0xFF | 11111111 |
| uint8_t | 255 | 0xFF | 11111111 |

Прогноз підтвердився: -1 має представлення 11111111.
Значення послідовності бітів визначається типом та способом
інтерпретації. Для uint8_t це 255, а для int8_t у додатковому коді — -1.

## 6. Межа unsigned integer

Прогноз: після збільшення 255 у uint8_t отримаємо 0.

| Дія | Фактичне значення uint8_t |
|---|---:|
| Присвоєння 254 | 254 |
| Збільшення до 255 | 255 |
| Збільшення 255 на 1 | 0 |
| Два збільшення від 255 | 1 |

Прогноз підтвердився.
8 бітів дозволяють зберігати 256 різних значень — від 0 до 255.
Під час збереження результату в uint8_t значення приводиться
за модулем 256.

Сам вираз 255 + 1 у C має значення 256; нуль отримуємо
після приведення або збереження цього результату в uint8_t.
Цей висновок не можна переносити на переповнення знакових цілих типів.

## 7–8. Байти в пам'яті та endianness

Досліджене число: 0x12345678.

Прогноз: 78 56 34 12, little-endian.

| Байт | Значення |
|---|---|
| byte 0 | 0x78 |
| byte 1 | 0x56 |
| byte 2 | 0x34 |
| byte 3 | 0x12 |

Фактичний результат: Little-endian. Прогноз підтвердився.

1. Адреси послідовних байтів зростають на 1.
2. За найменшою адресою розташований байт 0x78.
3. Це молодший байт числа, тому порядок є little-endian.
4. Саме число не змінилося. Порядок байтів визначає спосіб
   його розташування в пам'яті, а не змінює його значення.

Програма memory.c виводить фактичні адреси байтів.
Під час повторних запусків адреси можуть відрізнятися.

## 9. Один набір бітів — різні інтерпретації

| Інтерпретація | Значення |
|---|---|
| Binary | 01000001 |
| Hexadecimal | 0x41 |
| Unsigned decimal | 65 |
| ASCII character | A |

Самих бітів недостатньо для визначення змісту даних.
Потрібно знати тип, інтерпретацію та контекст використання.
Наприклад, 01000001 можна розглядати як число 65 або код символу A.

## 10. Підсумкова програма

Створено inspect.c, яка приймає ціле число від 0 до 255
і показує десяткове, шістнадцяткове та двійкове представлення.
Для друкованих ASCII-символів також виводиться символ.

Результат перевірки для введеного значення 65:

- Decimal: 65
- Hexadecimal: 0x41
- Binary: 01000001
- Character: A

## Контрольні питання

1. Біт — двійкова одиниця інформації зі значенням 0 або 1.
   У дослідженому середовищі байт містить 8 бітів.
2. За допомогою n бітів можна представити 2^n різних значень.
3. Діапазон 8-бітного unsigned integer: 0–255.
4. Діапазон 8-бітного signed integer у додатковому коді: -128–127.
5. Одна шістнадцяткова цифра відповідає чотирьом бітам,
   тому hexadecimal зручний для компактного запису байтів.
6. Біти 11111111 означають 255 як uint8_t та -1 як int8_t.
7. Після збільшення uint8_t зі значенням 255 отримуємо 0.
8. Для символу A зберігається числовий код 65 у цьому середовищі.
9. Endianness — порядок розміщення байтів багатобайтового значення.
10. Досліджена x86-64 система використовує little-endian.
11. sizeof(int) повертає розмір типу int у байтах.
12. Ті самі біти можуть представляти різні дані,
    оскільки їхній зміст залежить від типу та інтерпретації.

## Висновок

Експериментально визначено розміри основних типів C,
досліджено різні форми запису чисел і числові коди символів.
Підтверджено різну інтерпретацію однакових бітів у знаковому
та беззнаковому типах і перехід uint8_t від 255 до 0.
Дослідження байтів числа 0x12345678 показало порядок little-endian.
