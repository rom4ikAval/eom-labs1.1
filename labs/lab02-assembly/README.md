## 2. Отримання Assembly

Для `arithmetic.c` отримано Assembly у синтаксисах AT&T та Intel. Функція починається з мітки `main:`. У варіанті Intel знайдено:

```asm
mov DWORD PTR -12[rbp], 5
mov DWORD PTR -8[rbp], 7
mov edx, DWORD PTR -12[rbp]
mov eax, DWORD PTR -8[rbp]
add eax, edx
mov DWORD PTR -4[rbp], eax
```

Змінні `a`, `b` та `result` у цьому фрагменті представлені комірками стека зі зміщеннями `-12`, `-8` та `-4` від `rbp`. Їхні імена не збережені як назви операндів. Додавання виконує `add eax, edx`; виведення — `call printf@PLT`; повернення — `ret`.

У `main` нараховано **19 інструкцій**, включно з `endbr64`, прологом та епілогом; мітки й директиви `.cfi_*` не враховано. Одному рядку C може відповідати кілька інструкцій. Прогноз щодо послідовності обчислення суми підтверджено.

## 3. Арифметичні операції

| C | Фактична основна інструкція при `-O0` | Результат для 10 і 20 |
|---|---|---:|
| `a + b` | `add eax, edx` | 30 |
| `a - b` | `sub eax, DWORD PTR -24[rbp]` | -10 |
| `a * b` | `imul eax, DWORD PTR -24[rbp]` | 200 |

Після заміни операції змінилася арифметична інструкція та спосіб завантаження операндів. Для додавання використано `eax` і `edx`; для віднімання та множення другим операндом стала комірка пам'яті. Параметри функції надходять через `edi` та `esi`.

## 4. Реалізація if/else

У `condition.c` отримано такий фрагмент функції `max_value`:

```asm
mov eax, DWORD PTR -4[rbp]
cmp eax, DWORD PTR -8[rbp]
jle .L2
mov eax, DWORD PTR -4[rbp]
jmp .L3
.L2:
mov eax, DWORD PTR -8[rbp]
.L3:
pop rbp
ret
```

| Конструкція C | Відповідність в Assembly |
|---|---|
| `if (a > b)` | Завантаження `a`, `cmp eax, DWORD PTR -8[rbp]`, `jle .L2` |
| `return a` | `mov eax, DWORD PTR -4[rbp]`, перехід `jmp .L3` до спільного завершення |
| `else` | Мітка `.L2`, на яку переходимо, якщо `a <= b` |
| `return b` | `mov eax, DWORD PTR -8[rbp]`, далі спільні `pop rbp` і `ret` |

`cmp` встановлює прапорці за результатом порівняння. `jle` перевіряє умову знакового «менше або дорівнює» та переводить виконання до іншої гілки. Окремої машинної інструкції `IF`, еквівалентної конструкції C, тут немає.

## 5. Реалізація циклу

У функції `sum_to` змінна `sum` розміщена за `-8[rbp]`, `i` — за `-4[rbp]`, `n` — за `-20[rbp]`.

| Етап | Фактичний Assembly |
|---|---|
| `sum = 0` | `mov DWORD PTR -8[rbp], 0` |
| `i = 1` | `mov DWORD PTR -4[rbp], 1` |
| Початкова перевірка умови | `jmp .L2` |
| Тіло `.L3`: `sum += i` | `mov eax, DWORD PTR -4[rbp]`; `add DWORD PTR -8[rbp], eax` |
| `i++` | `add DWORD PTR -4[rbp], 1` |
| Перевірка `.L2`: `i <= n` | `mov eax, DWORD PTR -4[rbp]`; `cmp eax, DWORD PTR -20[rbp]` |
| Повторення | `jle .L3` |
| Повернення суми | `mov eax, DWORD PTR -8[rbp]`, епілог і `ret` |

Порівняння виконує `cmp`, переходи — `jmp` та `jle`. Ключового слова `for` у згенерованому Assembly немає. Після перевірки прапорців `jle` повертає виконання до тіла, якщо `i <= n`; інакше цикл завершується. Для `n = 5` отримано `15`.

## 6. Виклик функції

У `main` програми `operations.c` знайдено:

```asm
mov esi, 20
mov edi, 10
call calculate
mov DWORD PTR -4[rbp], eax
```

Код `calculate` починається з мітки `calculate:`; у дизасемблюванні її адреса — `0x1149`. Останні інструкції — `pop rbp` за `0x1165` та `ret` за `0x1166`. Результат типу `int` повертається через `eax`.

`call` зберігає у стеку адресу наступної інструкції та передає керування функції. `ret` використовує адресу повернення, щоб продовжити виконання після виклику. Без неї процесор не знав би, до якого місця програми повернутися.

## 7. Реальний машинний код

Наведені байти взято з фактичного результату `objdump` для `/tmp/lab02-operations`.

| Адреса | Machine-code bytes | Assembly | Довжина |
|---|---|---|---:|
| `0x1157` | `8b 55 ec` | `mov edx,DWORD PTR [rbp-0x14]` | 3 байти |
| `0x115d` | `01 d0` | `add eax,edx` | 2 байти |
| `0x1166` | `c3` | `ret` | 1 байт |

Виконуваний файл містить машинний код, дані та службові структури, а не текст Assembly як інструкції для виконання. `objdump` декодує байти у мнемоніки для зручності аналізу. Інструкції x86-64 мають змінну довжину, що видно з таблиці. Мнемоніки й операнди людині зрозуміліші за послідовності байтів.

Адреси наведено так, як їх показав `objdump` у дослідженому файлі; вони не обов'язково збігаються з адресами під час завантаження програми в пам'ять. За іншої версії компілятора або параметрів збірки адреси та байти можуть відрізнятися.

## 8. Порівняння -O0 та -O2

| Ознака | `-O0` | `-O2` |
|---|---|---|
| Функція `calculate` | 12 інструкцій, включно з `endbr64`; збереження параметрів у стеку | 3 інструкції: `endbr64`, `lea`, `ret` |
| Додавання | `add eax, edx` | `lea eax, [rdi+rsi]` |
| Виклик із `main` | Є `call calculate` | Виклик відсутній, використано готове значення 30 |
| Передача результату для друку | Результат виклику через `eax` | `mov edx, 30` |
| Функція виведення | `printf@PLT` | `__printf_chk@PLT` |

Оптимізований код `calculate`:

```asm
calculate:
    endbr64
    lea eax, [rdi+rsi]
    ret
```

У цьому випадку `lea` обчислює суму операндів без читання пам'яті за отриманою адресою. У `main` компілятор замінив обчислення з відомими аргументами готовим значенням `30`. Саме визначення `calculate` у файлі залишилося. У згенерованому коді також змінився виклик друку на перевірюваний `__printf_chk`.

Отже, C-код не має одного незмінного Assembly-представлення: оптимізація скорочує операції та звернення до пам'яті, зберігаючи спостережувану поведінку програми.

## 9. Прогноз результату компілятора

Для `answer`, що повертає `10 + 20`, прогнозовано варіант B — готове значення `30`.

**Фактично:** `mov eax, 30` присутня вже при `-O0`. При `-O2` функція `answer` містить лише `endbr64`, `mov eax, 30`, `ret`; у `main` також одразу повертається `30`, без `call answer`.

Прогноз підтвердився. Компілятор може обчислити константний вираз під час компіляції, оскільки це не змінює результату чи інших спостережуваних ефектів програми. `-O0` не означає обов'язкового буквального виконання кожної операції з вихідного тексту.

## 10. Аналіз analyze.c

Функція `sum_between(int a, int b)` визначає меншу та більшу межі через `if/else`, циклом додає всі цілі числа від `start` до `end` включно та повертає суму. Перевірено обидва порядки аргументів: `(3, 6)` і `(6, 3)` дали `18`.

### Конструкції у фактичному дизасемблюванні

| Елемент | Адреса | Інструкція / фрагмент |
|---|---|---|
| Початок функції | `0x1149` | `<sum_between>` |
| Порівняння `a` і `b` | `0x115a` | `cmp eax,DWORD PTR [rbp-0x18]` |
| Перехід до `else`, якщо `a > b` | `0x115d` | `jg 116d <sum_between+0x24>` |
| Початкове значення суми | `0x1179` | `mov DWORD PTR [rbp-0x8],0x0` |
| Початкова перевірка циклу | `0x1186` | `jmp 1192 <sum_between+0x49>` |
| Додавання `result += i` | `0x118b` | `add DWORD PTR [rbp-0x8],eax` |
| Збільшення `i` | `0x118e` | `add DWORD PTR [rbp-0x4],0x1` |
| Порівняння `i` та `end` | `0x1195` | `cmp eax,DWORD PTR [rbp-0xc]` |
| Повторення циклу | `0x1198` | `jle 1188 <sum_between+0x3f>` |
| Завантаження результату | `0x119a` | `mov eax,DWORD PTR [rbp-0x8]` |
| Повернення з функції | `0x119e` | `ret` |
| Перший виклик із `main` | `0x11b1` | `call 1149 <sum_between>` |
| Другий виклик із `main` | `0x11d6` | `call 1149 <sum_between>` |

### Відповідність C → Assembly → machine code

Байти отримано з власного executable `/tmp/lab02-analyze`.

| Конструкція C | Адреса | Assembly | Machine-code bytes |
|---|---|---|---|
| `result += i` | `0x118b` | `add DWORD PTR [rbp-0x8],eax` | `01 45 f8` |
| `i++` | `0x118e` | `add DWORD PTR [rbp-0x4],0x1` | `83 45 fc 01` |
| Порівняння для `i <= end` | `0x1195` | `cmp eax,DWORD PTR [rbp-0xc]` | `3b 45 f4` |

Для третього прикладу `cmp` є лише частиною реалізації умови: наступна `jle` за адресою `0x1198` має байти `7e ee` та виконує перехід за прапорцями. Виклик `sum_between(3, 6)` за `0x11b1` закодований байтами `e8 93 ff ff ff`; повернення за `0x119e` — байтом `c3`.

Виконувати в терміналі Codespaces. Файли `.c` мають міститися в `labs/lab02-assembly`.


## 12. Відповіді на контрольні питання

1. **Що таке ISA?** Архітектура системи команд: набір доступних процесору інструкцій, регістрів, форматів операндів і правил їх виконання.
2. **Чому CPU не виконує C-код безпосередньо?** C є мовою високого рівня; процесор декодує машинні інструкції своєї ISA. Потрібне перетворення коду.
3. **Assembly та machine code:** Assembly — текстові мнемоніки й операнди, machine code — байтове кодування інструкцій.
4. **Що робить `-S`?** Зупиняє компіляцію після генерації Assembly, до асемблювання та компонування.
5. **Навіщо `-O0`?** Вимикає більшість оптимізацій і полегшує зіставлення C з Assembly.
6. **Що таке operand?** Аргумент інструкції: наприклад, регістр, безпосереднє значення або комірка пам'яті.
7. **Для чого `mov`?** Копіює значення з операнда-джерела до операнда-призначення.
8. **Роль `cmp`:** Порівнює операнди, встановлюючи прапорці як після віднімання, але не зберігає різницю в операнд.
9. **Як реалізується `if`?** У дослідженому коді — порівнянням і умовним переходом за прапорцями до відповідної гілки.
10. **Як реалізується цикл?** Ініціалізацією, перевіркою умови, виконанням тіла, зміною лічильника та переходами.
11. **Для чого `call`?** Передає керування функції та зберігає адресу повернення у стеку.
12. **Для чого `ret`?** Повертає керування за адресою повернення зі стека.
13. **Чому немає відповідності «один рядок — одна інструкція»?** Один рядок може вимагати завантаження, обчислення й збереження; оптимізація також може об'єднати або прибрати операції.
14. **Що показує `objdump -d`?** Дизасемблювання секцій з інструкціями: адреси, машинні байти та їх Assembly-представлення.
15. **Чому `-O0` та `-O2` відрізняються?** Оптимізатор спрощує обчислення, прибирає зайві звернення до пам'яті та може усувати виклики функцій.
16. **Чи можна видалити частину C-коду?** Так, якщо це не змінює спостережуваної поведінки, наприклад для недосяжного коду або невикористаного обчислення без побічних ефектів.

З власних виконуваних файлів отримано реальні байти інструкцій. Порівняння `-O0` та `-O2` показало скорочення коду, використання `lea` для додавання і заміну виклику з відомими аргументами готовим результатом. Константний вираз `10 + 20` обчислено компілятором навіть при `-O0`.
